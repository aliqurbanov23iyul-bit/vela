# VELA Windows Connector

`agent/desktop.py` is a Tk desktop app and per-user installer. `scripts/build-desktop.py` creates one self-contained `desktop-dist/VELA-Setup.exe` containing Python, Tk, MetaTrader5, requests, pystray and Pillow. Build outputs and scratch files are ignored. No account file, user config, logs or environment file is bundled. `agent/desktop-requirements.txt` contains the UI/build dependencies. Builds run on Windows x64 only.

The setup window copies the executable to `%LOCALAPPDATA%/VELAConnector/VELA.exe` and creates a VELA desktop shortcut. Installation does not grant autostart or import an account. The installed app asks the user to choose their JSON. It validates the exact VELA HTTPS destination, UUIDs, login, token format and broker offset, then encrypts a whitelisted config using current-user Windows DPAPI to `connection.dat`. The original downloaded JSON remains unchanged; the app never displays or logs its secret.

One Windows session mutex prevents multiple desktop instances. A single non-daemon worker owns all MT5 reads using `main.run(stop_event, on_snapshot)`. No worker subprocess or console is launched. A snapshot callback is emitted only after a successful HTTP status. The GUI marks connected only for 45 seconds after that acknowledgment. Failures map to constant customer messages and do not expose raw exception text. Restart is explicit; no infinite reconnect loop or credential rotation.

Stop sets an event, wakes the polling delay and prevents new market jobs. Outstanding reads/uploads finish before the worker shuts down MT5's Python connection. No terminal process is terminated. Existing market request timeouts bound exit; no process-kill logic or trading is added. Source CMD remains compatible. Users must close the old CMD before starting the desktop app; the desktop mutex cannot retroactively lock a previously loaded legacy agent.

The tray runs on a Windows-supported secondary thread, sends menu events to Tk through a queue, and falls back to taskbar minimization if it fails. Autostart uses only HKCU Run and only for the installed executable; it is off by default. Uncheck autostart before removing the installed app manually. There is no signed installer, automatic update, or uninstall manager in this first version.

Tests: `python -m unittest discover -s agent -p test_connector.py -v`. The frozen `--self-test output.json` checks bundled imports, Tcl and a DPAPI round trip using synthetic bytes; it never reads user config, initializes MT5, sends network requests or writes startup settings. GitHub Actions builds and tests the same package before publishing an installer and SHA-256 checksum in Releases. The setup/desktop visual appearance and real system tray interactions require a Windows user review; native UI automation was unavailable during implementation.

Installer fix: desktop shortcuts use native Windows COM via pywin32, including redirected OneDrive desktops. No PowerShell subprocess is required. Shortcut failure is non-fatal. Copy and launch failures show a specific stage and Windows error code; signing-policy blocks are reported explicitly without weakening protection. The frozen self-test also creates a synthetic shortcut only in its temporary test directory.
