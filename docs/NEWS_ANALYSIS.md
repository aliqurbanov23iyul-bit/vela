# Official news context and analysis evidence

The backend polls fixed official RSS endpoints for FED monetary policy, FED speeches, ECB press releases, BLS CPI and BLS employment releases. It uses publisher headlines, RSS summaries (maximum 600 characters), original links and publication timestamps. It does not scrape full articles or claim to provide Bloomberg/Reuters access, all breaking news, live consensus data or an economic calendar. No news API key is required. BLS may reject automated access or return HTML instead of RSS; these are reported as failures and are not bypassed.

Migration 009 adds a shared cache containing only public publisher metadata. It contains no user, tenant or account information. Fixed source rows grant runtime SELECT/UPDATE only. Database leases and a five-minute next-check timestamp bound fetch frequency across instances. Network requests occur outside transactions, have eight-second timeouts, reject redirects and responses above 512 KB, and use only hardcoded HTTPS endpoints. XML DTD/entities are rejected; item links must match the publisher HTTPS host. Dates outside the preceding 14 days or over five minutes in the future are excluded. Failed or stale sources are never passed as current AI evidence. Empty feeds do not mean there are no important news events.

The public GET /api/news returns only those public source statuses and headlines, without user data, credentials or account analyses. It refreshes a due cache. An authenticated MT5 market upload also refreshes a due cache while AI is cooling down, paused, or blocked by market data quality. With an active connector, refresh opportunities occur every minute; remote feeds are fetched no more often than once per five minutes. There is no standalone scheduler if every connector and browser is offline.

Each new market analysis selects up to two headlines per publisher, maximum six. EURUSD uses USD/EUR context; XAUUSD uses USD context. The exact selected articles, source health and market quote/M5/H1 timestamps are stored in the account's existing RLS-protected analysis result. The AI must return a separate news_assessment with a substantive summary and valid supplied NEWS source IDs. Its cited IDs must also occur in the overall source list. Missing or fabricated references fail the provider response. Input evidence remains untrusted data, not instructions.

The customer view distinguishes latest publisher health from the exact historical context sent in a particular analysis. Only a COMPLETED response with a validated news_assessment displays the green news-commentary status. Sent headlines alone do not display an analyzed status. Old technical-only runs remain explicitly labeled as having no news context. This records model output and traceable inputs; it does not prove the model's reasoning or forecast is correct.

Result format 3 contains newsEvidence, newsAssessment and marketEvidence. One bounded upgrade from a successful old format-2 technical-only result can run on a different closed candle, within the existing daily budget. Format-3 results cannot trigger repeated upgrades. Existing pre-format-2 invalid-output recovery is preserved. The authenticated market upload response also exposes minimal latest-analysis status, timestamps and public source counts to its own connector, never account credentials.

Trading remains disabled. The full calendar/market-session/account-risk gates are unchanged, every market result's action is NO_TRADE, and the Windows agent remains read-only with no order_send call. Profitability is not established by this integration; meaningful evaluation still requires cost-aware backtesting and demo forward results.

Validation covers XML/URL/date rejection, response size/redirect limits, cache leases and permissions, failed/stale evidence exclusion, symbol context selection, AI source-reference enforcement, and bounded news upgrades under the daily budget.
